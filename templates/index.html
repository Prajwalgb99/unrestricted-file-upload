    Step 6: Why is checking only the extension insufficient?
    An extension is just text in the filename and the user controls it. Anyone can rename program.exe to photo.png, or the reverse. Only the real content (magic bytes), the declared MIME type, the size and a server-generated filename together give reliable protection.

    Learn: The Vulnerability

    What is it?

    A web app lets users upload files but does not properly check their name, type, content or size. The server then stores or processes whatever it receives.

    How does it work?

    The attacker uploads a malicious file disguised as a harmless one (e.g. a script named photo.jpg). If the server stores it somewhere it can be run or opened by others, the attack succeeds.

    Why is it dangerous?

    It can lead to remote code execution, defacement, malware distribution, data theft, stored XSS, server overload (huge files) and overwriting of important files.

    Real-world implications

    Compromised servers, leaked customer data, ransomware entry points, reputation damage and legal penalties. Upload flaws are a recurring finding in web security assessments.

    Common causes

    • Trusting the file extension
    • Trusting the browser's Content-Type
    • No size limit
    • Original filename used on disk
    • Uploads stored in a web-executable folder

    Prevention

    • Extension allowlist
    • MIME + magic-byte validation
    • Maximum size
    • Secure, random filenames
    • Block path traversal
    • Store outside the web root, never execute
